mlir-interpreter query with caching

Every result of @main is queried in source order through one semantic cache, so equal computations hit even when their operands are different SSA values. The C++ interpreter is compiled to WebAssembly and runs in a Web Worker on this page.

    Budget per value

    Each result's query gets this many steps, shared by hashing, equality and evaluation. The cache lives for the whole run, and every run starts with an empty one.

    Cache

    hit or miss is the lookup for the result's own operation. — means the operation isn't cached, like a constant, or hashing ran out of budget first.

    Direct query

    Queries one value by name, a result or a block argument, before or after all of @main's rows. It uses the same engine and budget per value, so it shares their cache. Every Query is a fresh run.

    Control flow

    Nothing is executed. Values are queried on demand, so block arguments and results of branches, regions and calls are unknown.
